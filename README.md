# Весь Спектр — бетонные лестницы

Готовый лендинг на **Next.js 16.3.4 + React + TypeScript**, App Router.
Сайт не опубликован. Архив содержит исходники, lockfile и локальные фотографии.

## Запустить у себя

Понадобится Node.js 20.9+ (рекомендуется Node.js 22 LTS) и npm.
Распакуйте архив, откройте терминал в папке `vesspektr-next`:

```bash
npm ci
npm run dev
```

Откройте http://localhost:3000.
Доступ к интернету нужен для установки зависимостей. Изображения и шрифты не загружаются со сторонних сайтов: используется системный шрифт, фотографии находятся в `public/images`.

Для локальной production-сборки:

```bash
npm run build
npm start
```

Проверка типов: `npm run typecheck`.

## Что включено

- Адаптивная главная страница: первый экран, конструкции, галерея с увеличением фотографий, отделка, этапы, запрос сметы, FAQ, контакты.
- Мобильное меню и закреплённые кнопки звонка и расчёта.
- Форма с выбором конфигурации и отделки, проверкой телефона и согласием на обратную связь.
- Серверная предварительная генерация основного контента, один H1, последовательные заголовки, метаданные и canonical.
- Open Graph на основе существующей фотографии; JSON-LD Organization, Service, FAQPage; robots.txt и sitemap.xml.
- Оптимизация изображений средствами Next.js, отложенная загрузка галереи и приоритетная загрузка первого изображения.
- Клавиатурная навигация, фокус, нативный диалог с закрытием Escape и возвратом фокуса, поддержка reduced motion.
- Серверный API для CRM, отслеживаемые события кнопок и заявки, UTM / gclid / yclid в CRM-запросе.

## Как работает запрос расчёта

**Без настройки интеграции** форма собирает параметры и показывает кнопку «Открыть письмо». Она открывает почтовое приложение с адресом `vesspektr@gmail.com` и подготовленным текстом. Пользователь самостоятельно отправляет письмо. До этого сайт не заявляет, что запрос доставлен. Если почтовое приложение не настроено, рядом доступны адрес и телефон.

**Для прямой отправки в CRM:** скопируйте `.env.example` в `.env.local` и укажите:

```dotenv
NEXT_PUBLIC_SITE_URL=https://your-domain.by
SITE_INDEXABLE=false
LEAD_WEBHOOK_URL=https://your-crm.example/api/leads
LEAD_WEBHOOK_TOKEN=your-secret-token
```

Перезапустите dev-сервер или пересоберите production. Страница выбирает режим формы при сборке. Секреты не передаются браузеру; у `LEAD_WEBHOOK_TOKEN` не должно быть префикса `NEXT_PUBLIC_`.

Обработчик `/api/lead` отправляет JSON методом POST; при заданном токене — заголовок `Authorization: Bearer …`. CRM должна возвращать 2xx только после принятия заявки:

```json
{
  "name": "Имя клиента",
  "phone": "+375291234567",
  "city": "Минск",
  "comment": "Высота этажа 3 м",
  "kind": "Г-образная",
  "finish": "Дерево",
  "consent": true,
  "attribution": { "utm_source": "google", "utm_campaign": "concrete_stairs" },
  "source": "vesspektr-landing",
  "createdAt": "ISO 8601"
}
```

Сервер проверяет Origin, тип и размер тела (включая поток), телефон, длины полей, варианты выбора и согласие. Есть скрытое поле против простых ботов, таймаут и обработка ошибок. Публичный запуск API предполагает ограничение частоты запросов на вашем reverse proxy / CRM. Локальной базы заявок и отправки SMTP в проекте нет. Внешняя CRM не подключена и фактическая доставка не проверялась: credentials не предоставлены.

## SEO и публикация

1. В `.env.local` установите конечный origin в `NEXT_PUBLIC_SITE_URL`: протокол и домен без пути и завершающего слеша.
2. **Для публичного сайта установите `SITE_INDEXABLE=true` и выполните новую сборку.** По умолчанию тестовые сборки закрыты от индексации через robots и метатег.
3. Добавьте `/sitemap.xml` в Google Search Console и Яндекс Вебмастер, подтвердите владение доменом в этих сервисах.
4. Настройте HTTPS и один основной вариант домена. По умолчанию canonical указывает на `/`. Старый `/betonnie-lestnici` перенаправляется на `/` постоянным редиректом 308. Это вариант для размещения нового лендинга в корне отдельного домена/поддомена; если сохраняете существующий многостраничный сайт, согласуйте маршруты перед заменой.
5. Проверьте реальную мобильную скорость после размещения: результаты зависят от сервера. Lighthouse / PageSpeed в этой среде не запускались.
6. Подключите при необходимости фактические реквизиты организации и утверждённую политику обработки данных. Неизвестные адрес, УНП и сроки хранения не выдумывались.

Тексты написаны для посетителя, с естественными запросами «бетонные лестницы», «на заказ», «на второй этаж», «изготовление», «Беларусь». Цены, отзывы, гарантийные сроки и рейтинги не придуманы. Разметка и SEO-структура не гарантируют позиции, расширенный сниппет или одобрение рекламы.

## Google / Яндекс: события

Идентификаторы счётчиков не предоставлены, поэтому трекеры не подключены и чужие идентификаторы со старого сайта не скопированы.
В `app/ui.tsx` события передаются в существующий `window.dataLayer` и через DOM-событие `vesspektr:conversion`:

| Событие | Действие |
| --- | --- |
| `phone_click` | Клик по телефону |
| `email_click` | Клик по почте в контактах |
| `estimate_prepared` | Подготовлено письмо с параметрами |
| `email_request_click` | Открыто письмо, доставка не подтверждена |
| `lead_success` | CRM вернула успешный ответ |

При подключении GTM создайте Custom Event triggers и нужные конверсии Google Ads. Для Яндекс Метрики можно слушать `vesspektr:conversion` и передавать нужные имена в `ym(ВАШ_ID, 'reachGoal', event.detail.event)`. Загрузку счётчиков и согласие на аналитику настройте в соответствии с вашим сценарием. Не передавайте телефон, имя и комментарий в аналитику. Основная подтверждённая конверсия формы — `lead_success`; открытие почты является отдельной микроконверсией.

Атрибуция берётся из URL при отправке и включается только в JSON для CRM; для этого одностраничного лендинга localStorage и cookie не требуются. Долговременная атрибуция между визитами не реализована.
